# Module audit — shared UI

**Status: partial audit; strict acceptance is not met because browser review and complete behavioral/API verification remain outstanding.** Source `8a6aac3` on `develop`.

## Prioritized observations

- **P2 UI-A01 — Generic feedback alongside field errors.** `src/components/patterns/action-form.tsx:85` puts client errors in `fieldErrors`; lines 107–113 render `ActionFeedback` with the generic error title. The code supports the concern, but no browser verification was performed for this audit. Proposal: evaluate conditional feedback with app owners. Risk: misleading feedback; the separate forms-UX worktree already proposes a change and is outside this audit.
- **P2 UI-A02 — Heading contract needs review.** `src/components/patterns/card.tsx:27` renders `CardTitle` as `h3`; `src/components/layout/page-header.tsx:31` renders `h1`. In CRM home the combination can skip `h2` (`app/[orgSlug]/(home)/page.tsx:42,94`). Proposal: review heading semantics and shared component API. Risk: heading navigation; browser/axe verification pending.
- **P2 UI-A03 — AsyncCombobox mirrors props into state in an effect.** `src/components/ui/async-combobox.tsx:42-58` merges `initialOptions` and `selectedOption` into `options` with `setOptions`. This is derived state and can add a commit when those props change. Proposal: consider deriving merged options during render; risk: redundant work/flicker is unmeasured.
- **P2 UI-A04 — Textarea synchronizes a controlled count through an effect.** `src/components/ui/textarea.tsx:19-22` copies `value` length into state after render. Proposal: derive displayed count from controlled `value` and retain local state only for uncontrolled input; no latency impact is claimed.
- **P2 UI-A05 — KanbanBoard implementation is unusually large.** `src/components/patterns/kanban-board.tsx:1` has 1,320 lines and a 38,857-byte published source module. Proposal: consider extracting internal drag measurement/interaction helpers without changing the public API; risk is maintainability, not measured performance.
- No P0 finding or P1 measured performance impact is established by this partial audit.

## Method and limits

The checked subject is the `develop` commit identified below, not the separate forms-UX worktrees. Builds used the literal public fixture values in CI. No real database or browser was used for this audit.

These tables distinguish static evidence from measured outcomes. A filename, a lexical marker, a test filename, an import, or an observed commit count does not prove an interaction, accessibility, internationalization parity, latency, visual stability, permission or production performance. Definition of Done items 1–8 require independent checks per route and are **not certified** by this inventory. Server render timing, interaction latency, INP, long tasks, hydration and production commits require browser and authorized-environment measurements. No P1 performance defect is claimed from Profiler counts alone.
